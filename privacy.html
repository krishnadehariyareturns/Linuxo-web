THE BORING BUT IMPORTANT PART

Privacy Policy.

This policy explains what information the Linuxo website and Linuxo Discord bot process, why they process it, and what choices you have.

Effective date: 18 November 2026 · Website: maybelinuxo.kdns.fr

1. Who this policy covers

This policy covers the Linuxo website at maybelinuxo.kdns.fr and the Linuxo Discord bot associated with the Linuxo GitHub project. Discord is a separate service with its own privacy policy and terms.

2. Information processed by the Discord bot

When a person uses a Linuxo slash command or button, the bot's telemetry system may place interaction and diagnostic information into a log record. The context can include:

  • Discord user ID and username/tag;
  • server (guild) ID and name, channel ID, and interaction ID;
  • command name, subcommand, or button identifier;
  • event timestamp, log level, command duration, status, and diagnostic/error information; and
  • technical runtime details such as bot version, Node.js version, process ID, hostname, and shard ID.

The logger also records relevant lifecycle events, such as bot startup, shutdown, and guild joins or departures.

The bot currently requests only Discord's Guilds gateway intent. The inspected code does not request the privileged Message Content or Guild Members intents, and it does not read ordinary message content or collect member lists through those intents.

The inspected implementation contains no database integration. This does not mean logs are never retained: logs may be kept by the machine or hosting service running the bot, depending on its configuration.

3. Where bot logs may be sent and redaction

Console logging is enabled by default. The operator may also configure:

  • a local JSON-lines log file using the LOG_FILE setting; and
  • Discord webhook destinations for log, error, security, performance, or debug categories.

Webhook destinations and file logging depend on the operator's configuration. The logger's redaction feature is enabled by default in the inspected source configuration. Before log records are passed to configured transports, it redacts recognized sensitive structured fields, including fields for Discord user, guild, channel, interaction, and message identifiers. It also attempts to scrub credentials and other recognizable secrets.

Redaction can be disabled by the operator with LOG_REDACTION_ENABLED=false. Redaction is not a guarantee that every identifier or personal detail will be removed: arbitrary free-form text may not be fully scrubbed, and the actual behavior depends on the deployed configuration.

4. Website information and third-party services

The supplied website code does not implement an account system, first-party analytics, advertising trackers, or a first-party cookie-based profile. It loads some resources from third parties:

  • Google Fonts provides website fonts.
  • Cloudinary serves team profile images.
  • jsDelivr may serve the optional Anime.js animation library when motion is enabled.
  • Website hosting and delivery providers may process technical request data, such as IP address, browser details, requested URL, and request time, for delivery, reliability, and security.

Those providers process requests under their own terms and privacy policies. The website's hosting, CDN, DNS, and server-log settings can affect what technical data is retained. We cannot determine those provider-side settings from the website source files alone.

5. Why information is processed

Bot interaction and lifecycle data is used to operate commands and buttons, diagnose errors, monitor reliability and performance, protect the bot from misuse, and understand whether commands are completing successfully. Website resource requests are needed to display the site and its images, fonts, and optional animations.

6. Retention and deletion

In the inspected source configuration, automatic retention cleanup for Discord webhook log messages is enabled by default with a 14-day retention period. The operator can change this using LOG_RETENTION_DAYS or disable automatic cleanup using LOG_RETENTION_ENABLED. The cleanup system tracks webhook message identifiers and timestamps so expired webhook messages can be deleted; it does not use that tracking file as a copy of the log content.

That 14-day default applies to webhook messages handled by this cleanup feature, not necessarily to every copy of a log. Console output may be retained by the host, and optional local log files may remain according to the operator's and hosting provider's settings. Third-party services may apply their own retention rules. The deployed environment may differ from the source defaults described here.

If you have a privacy request, contact the project maintainers through the official GitHub project. Do not post private identifiers or other sensitive information in a public issue.

7. Security

The logger includes automatic credential redaction, and the bot uses Discord's interaction system rather than requesting message-content access. Redaction reduces the amount of sensitive information in logs but cannot guarantee that every sensitive value is removed. No online service can promise perfect security, so avoid sharing passwords, tokens, or other secrets in public Discord channels or project issues.

8. Changes to this policy

This policy may be updated when the website, bot, or its data practices change. The effective date at the top will be updated when a revised policy is published.

9. Scope and questions

This page describes the behavior visible in the website files and the Linuxo bot source inspected for this release. Hosting-provider settings, environment variables, and future code changes may add or change processing. For questions, use the project's official GitHub repository and avoid sharing sensitive personal information publicly.
