THE BORING BUT IMPORTANT PART

Privacy Policy.

This policy explains what information the Linuxo website and Linuxo Discord bot process, why they process it, and what choices you have.

Effective date: 22 November 2026 · Website: maybelinuxo.kdns.fr

1. Who this policy covers

This policy covers the Linuxo website at maybelinuxo.kdns.fr and the Linuxo Discord bot associated with the Linuxo GitHub project. Discord is a separate service with its own privacy policy and terms.

2. Information processed by the Discord bot

Discord sends the bot an interaction payload when someone uses a slash command or button. Linuxo keeps the diagnostic information it writes to logs deliberately limited. Log records may contain:

  • the slash-command name and optional subcommand, but not command option values;
  • event timestamp, severity, outcome, and command execution duration;
  • sanitised error name and message, numeric error code, and HTTP status;
  • Linuxo bot version and Node.js version; and
  • aggregate command counts, timings, and startup or shutdown diagnostics.

Linuxo does not put Discord user IDs or tags, server IDs or names, channel IDs, interaction IDs, or button custom IDs into its diagnostic records. It does not log ordinary message content, command option values, or member lists. Button logs identify only that a button interaction occurred, not which button identifier was used.

A small number of Discord identifiers are still needed briefly in application memory. The bot compares the clicking user's ID with the original invoker's ID to authorise deletion of a /startup panel. It also uses an interaction ID and guild ID to manage and clean up short-lived panel refresh timers. These values are used for those operational checks; they are not added to logs or saved as user profiles or interaction history. Timer entries are cleared when the panel expires, is deleted, the bot shuts down, or the bot leaves the relevant server.

The bot currently requests only Discord's Guilds gateway intent. The inspected source does not request the privileged Message Content or Guild Members intents and does not read ordinary message content or collect member lists through those intents.

The inspected implementation contains no user database or persistent user-profile store. Discord and the hosting provider may separately process information under their own systems and policies.

3. Where bot logs may be sent and redaction

Console logging is enabled by default. Webhook delivery is disabled by default and only sends records to Discord when the operator explicitly enables it with LOG_WEBHOOK_ENABLED=true and configures one or more LOG_WEBHOOK_* destinations. Local JSON-lines file logging is disabled unless the operator sets LOG_FILE.

Redaction is always applied by the logger and cannot be disabled through its environment configuration or logger overrides. It removes recognised sensitive structured fields and scrubs common credentials, webhook tokens, email addresses, IPv4 addresses, and long numeric identifiers from log strings. The logger does not retain error stack traces.

Redaction is a protective filter, not a guarantee that every possible personal detail will be detected. Unexpected information could still appear in an error message or in future custom log fields. The project therefore avoids adding user-supplied content and raw Discord interaction objects to log records in the first place.

4. Website information and third-party services

The supplied website code does not implement an account system, first-party analytics, advertising trackers, or a first-party cookie-based profile. It loads some resources from third parties:

  • Google Fonts provides website fonts.
  • Cloudinary serves team profile images.
  • jsDelivr may serve the optional Anime.js animation library when motion is enabled.
  • Website hosting and delivery providers may process technical request data, such as IP address, browser details, requested URL, and request time, for delivery, reliability, and security.

Those providers process requests under their own terms and privacy policies. The website's hosting, CDN, DNS, and server-log settings can affect what technical data is retained. We cannot determine those provider-side settings from the website source files alone.

5. Why information is processed

The limited bot diagnostics are used to confirm that commands and buttons are operating, measure command duration, identify failures, and maintain service reliability. Temporary Discord identifiers are used only where needed for button authorisation and panel-timer cleanup. Website resource requests are needed to display the site and its images, fonts, and optional animations.

6. Retention and deletion

Webhook delivery is off by default. When the operator enables webhook logging, automatic cleanup of webhook log messages is enabled by default with a 14-day retention period. The operator can change this using LOG_RETENTION_DAYS or disable cleanup using LOG_RETENTION_ENABLED. The cleanup index stores the webhook message ID, category, and creation time so expired messages can be deleted; it does not store the log contents, webhook URLs, or user account IDs.

The 14-day period applies only to webhook messages managed by this cleanup feature. It does not guarantee removal of copies retained by Discord, hosting providers, backups, container logs, or external log collectors. Console output may be retained by the host. Optional local log files may remain according to the operator's and hosting provider's settings. The deployed environment may differ from the source defaults described here.

If you have a privacy request, contact the project maintainers through the official GitHub project. Do not post private identifiers or other sensitive information in a public issue.

7. Security

The logger always applies redaction, omits Discord identity fields from diagnostic records, and does not retain error stack traces. The bot requests only the Discord Guilds intent and uses temporary in-memory identifier checks for the limited operational purposes described above. These measures reduce unnecessary data exposure but cannot guarantee perfect security. Avoid sharing passwords, tokens, or other secrets in public Discord channels or project issues.

8. Changes to this policy

This policy may be updated when the website, bot, or its data practices change. The effective date at the top will be updated when a revised policy is published.

9. Scope and questions

This page describes the behavior visible in the website files and the Linuxo bot source inspected for this release. Hosting-provider settings, environment variables, and future code changes may add or change processing. For questions, use the project's official GitHub repository and avoid sharing sensitive personal information publicly.
